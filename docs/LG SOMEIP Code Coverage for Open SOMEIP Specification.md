## 12. Recommendations

**Notable gaps / partials worth verifying manually:**

- **§9.6 Non-SOME/IP service announcement (`otherserv` config string)** — no clear   implementation; multiple requirements marked N/A.
- **§9.8.4 Security considerations** (`feat_req_someipsd_1135/1136/1149`, topological IP-address validation) — not visible.
- **§9.3.4.7-8 IPv4/IPv6 SD Endpoint Options** (Type 0x24 / 0x26) — only generic endpoint option handling was observed; the dedicated *SD* endpoint option type is required for reboot detection across NAT/proxy scenarios.
- **§9.3.4.9 MAC-Groupcast Endpoint Option** (Type 0x15) — not observed.
- **§5.4 Optional / Bitfield / Union/Variant** serialization (`feat_req_someip_682`, `_817`, `_263..289`) — basic types and structs are handled; advanced AUTOSAR variants need verification.
- **§9.3.2 Explicit Initial Data Control Flag** (`feat_req_someipsd_1187/1188`) — flag bit handling not visible.
- **§9.5.5 IP-address topological correctness check** (`feat_req_someipsd_1135`) — receivers should reject endpoint options with addresses outside the SD subnet.
- **§10 TP timeout for incomplete reassembly** (`feat_req_someiptp_790`) — no explicit reassembly timeout visible; only sequence/session-id resets.
- **§6.5 Field semantics** (getter/setter/notifier triplet) — events exist, but the field abstraction with on-change/epsilon/cyclic strategies needs targeted review.
- **§9.3.5 Boundary checks** for option indices in incoming SD messages — relies on upstream parsing, not explicit defensive checks.

**Recommendations**
1. **Add an SD endpoint option (type 0x24 / 0x26)** for IPv4/IPv6 SD endpoint announcement (§9.3.4.7-8). The reboot-detection guarantees of §9.3.2 rely on it for any non-trivial routing topology.
2. **Add topological IP address validation** for incoming SD endpoint options (§9.5.5 / `feat_req_someipsd_1135`). Rejecting addresses outside the SD subnet is a security control against off-LAN injection.
3. **Add reassembly timeout** for SOME/IP-TP (§10 / `feat_req_someiptp_790`); current implementation only resets on sequence/session-ID mismatch.
4. **Implement Explicit Initial Data Control Flag** (§9.3.2 / `feat_req_someipsd_1187/1188`) and the `Initial Data Requested` flag bit in `SubscribeEventgroup` entries — needed for clean reconnects without firing duplicate initial events.
5. **Add `otherserv` / non-SOME/IP service announcement** support (§9.6) if there is any plan to advertise diagnostic or non-SOME/IP services through SD.
6. **Verify field semantics** (§6.5) — ensure each Field has at most one getter, one setter, one notifier and that change-detection / epsilon / cyclic strategies are configurable per feat_req_someip_633` and `_1092`.
7. **Manual code review** of items marked *Partial* — the auditor only confirmed the mechanism exists, not that the exact specification wording is satisfied.
